# 局域网联机对战

新增第四种“联机对战”，原有闯关打怪、计时拆砖、同屏对战仍通过原来的离线流程启动。使用 Godot 4.7 的 ENetMultiplayerPeer 和高层 RPC；无需服务端安装或外部账号。

## 玩家操作

两台电脑使用同一版本的桌面游戏，并连接同一局域网。房主创建房间，来宾输入房间显示的 IPv4 地址和相同端口（默认 UDP 24566）。首次启动时允许游戏通过防火墙；如果显示多个地址，应选择双方能互通的局域网地址。

左右分别是房主与来宾，标注本机、远端和在线状态。每人只能操作自己的面板；不能选择对方已占用的角色。改角色撤销自己的准备，不改动对方。双方准备后只有房主能点击开始，或按 F5 / 手柄 Start。

两端都使用各自电脑的 1P 单人键位/手柄设置。默认方向键/WASD 移动、空格放弹、Q 技能。网络 Peer ID 与本地手柄编号无关；来宾的本地 1P 输入只被房主应用到网络 2P。

规则复用同屏对战：两人、先得两分、自动切换回合、超时死亡加速。结算时“返回联机大厅”让双方回到房间，清除双方准备后重新选择；“退出联机”断开连接并返回主菜单。对局中 Esc / Start 打开离开确认，网络对局不会被一方暂停。

## 文件与隔离

| 文件 | 责任 |
|---|---|
| `scripts/net/LanSession.gd` | 独立 SceneMultiplayer、ENet 生命周期、权限校验、大厅状态机、输入及权威快照、断线恢复 |
| `scripts/net/NetSnapshot.gd` | 只包含基本值的状态编码，稳定炸弹 ID、客户端对象复用与位置插值端点 |
| `scenes/lan_lobby.tscn`、`scripts/net/LanLobby.gd` | 网络地址/端口、创建/加入、独立左右选角与准备、连接反馈 |
| `scripts/LobbyPlayerPanel.gd` | 复用现有动效预览，增加可选网络身份文案和远端只读状态；本地准备室默认行为保持原样 |
| `scripts/Menu.gd` | 四模式 2×2 卡片及独立网络入口 |
| `scripts/Main.gd` | 网络模式绑定视图、读取本机单人输入、处理离开/结算/清理；离线仍直接调用原 GameEngine |
| `scripts/Hud.gd`、`scripts/Overlay.gd` | 联机身份、远端技能提示、网络结算按钮文案 |

网络 API 只挂在 `Main/LanSession` 子树，不替换整个游戏的默认 multiplayer。前三种模式不需要网络服务，离线 GameEngine、Rules、Match、地图、技能与 InputSettings 的规则未改造。只在选择创建/加入后建立 ENet 连接；退出关闭 ENet，释放世界、房间玩家、待处理输入和视图。

## 权威与同步

- 房主 Peer ID 为 1，只允许一个来宾连接。协议标识为 `bombit-lan-1`；版本不匹配明确拒绝，未完成握手的连接超时释放。客户端不能指定自己属于哪名玩家。
- 角色、准备与返回大厅的请求通过可靠 RPC 到房主，房主检查来源 Peer ID、房间阶段和角色范围/占用。开局先进入 loading 锁，收到来宾已加载确认后再运行；所有对局消息都带递增的 epoch，避免上一局的输入影响新对局。
- 房主以 60Hz 运行原对战 GameEngine。来宾只发送方向、轴优先级及递增放弹/技能按压计数，不发送位置、炸弹对象、伤害、道具拾取或分数。房主验证来源、epoch、递增序号、方向范围和计数变化，然后由原规则检查人数、生命、炸弹配额、格子和技能冷却。
- 输入为顺序不可靠通道，重复携带按压计数避免单个丢包直接丢失按钮边沿；重复或过期序号不重复消费。超过 300ms 没有新输入时停止远端移动。不会无限沿用最后一次移动方向。
- 房主每三帧（20Hz）发送完整权威状态，基本 Variant 值经过 DEFLATE 压缩，通过独立可靠通道传输，避免大包不可靠分片。客户端只恢复状态，**不运行 GameEngine，不独立结算伤害、连锁、拾取或胜负**。
- 快照包含地图及版本、障碍、道具、机关、炸弹倒计时、火焰、玩家朝向/属性/技能与比分。炸弹使用单局递增 ID，接收端按 ID 保留对象，避免重复创建。玩家对象按 p1/p2 保留，位置使用约 50ms 的插值窗口；换图/大位移直接校正。
- 音效/粒子事件通过另一个可靠通道发送，并带事件序号去重；胜负状态通过可靠最终快照传输，双方只进入一次结算。
- 心跳确认连接，静默超过六秒清理。来宾退出时房主取消当前对局并回到等待大厅；房主退出时来宾收到明确提示。重新加入创建新连接和玩家身份，需要双方重新准备，不从断线现场续局。

## 验证

统一入口：`cmd /c E:\BombitGodot\tools_test_locked.cmd`。联机套件可单独运行 `test_lan`。

`test_lan` 会启动两个真正独立的游戏进程，通过 ENet 的 127.0.0.1 连接，使用真实 Main、大厅和结算流程。为稳定复现，房主测试夹具清空内部地图并布置可破坏砖与道具；实际放弹、引爆、连锁、拾取、死亡、回合和两分获胜均由原游戏规则执行，未通过手工指定胜者绕过规则。覆盖：

- 独立选角、远端面板不能替对方选择、双方准备、重复开局锁。
- 来宾移动、两颗炸弹、连锁爆炸、软砖变化、道具拾取与属性、技能和死亡。
- 最终权威地图、玩家、炸弹、道具、属性和比分摘要在两个进程中相同。
- 结算返回大厅、重新准备再开局、局中断线、不同 Peer ID 的重连、房主退出提示。
- 未认证来源、旧 epoch、非法方向、对局中改角、版本不匹配、缺少玩家时开局等请求被拒绝。
- 退出后分别启动闯关、拆砖、本地双人，并用实际键盘事件确认角色仍可移动。
- 编解码后对象独立、同 ID 炸弹复用、新炸弹不复用旧 ID、退出清理。

本轮联机套件为 **58 项断言**；原有七套件 302 项，加上 CLI 的 20 项，合计 **380 项断言**。既有 `test_art` 无头绘制覆盖限制继续适用，断言数量不等于完整美术或硬件覆盖。

Godot AI MCP 检查了四模式主菜单、网络入口、等待加入、双方准备和房间断线反馈。另以独立图形客户端加入 MCP 房主，核对来宾的联网对局画面；`tests/preview_lan_client.gd` 为可手动运行的诊断工具，不属于自动测试，预览保存在 `.godot/lan-client-*.png`，设置文件与玩家存档隔离。

## 当前范围

已验证同机两个独立进程的实际网络收发，尚未在两台实体电脑、不同网卡/路由器和真实丢包环境中联调。没有房间自动发现、互联网穿透、旁观或中途续局；这些不属于本轮两人局域网范围。优先保持房主权威与同步正确，目前未增加客户端预测/回滚，网络延迟较大时操作反馈会变慢。网页导出不能使用 ENet，界面会提示改用桌面版；原有离线模式仍保留。
