# 双人选角与准备室

## 实际工程结构与问题来源

工程为 Godot 4.7.2、GDScript。主场景是 `main.tscn`，节点为 `Main` → `Board`、`Actors`、`UILayer/Hud`、`UILayer/Menu`、`UILayer/Overlay`、`UILayer/Replay`。Main 管理菜单与实际对局的状态，不另外切换完整游戏场景。

原选角 UI 全部由 Menu 自绘。两名玩家虽然有 `char_index[0/1]`，却共用 `player`、`nav_focus` 和 `poll_nav()` 合并后的输入，无法判断这次确认属于谁。更直接的串联原因是 `_select_char()` 在选中对方角色时会替对方重选角色；原 `ensure_distinct()` 也直接写另一方索引。旧流程没有独立准备状态，由共享的“当前玩家”决定下一步或开局。

已移除主动改写另一玩家角色的逻辑。仍保留不同角色约束：切换时跳过对方角色，点击占用角色时拒绝并提示。

## 文件与职责

| 文件 | 职责 |
|---|---|
| `versus_lobby.tscn` | 双人准备室，左右 `Player1Panel` / `Player2Panel` 独立节点 |
| `scripts/VersusLobbyState.gd` | 两个独立 PlayerChoice 对象、角色占用规则、准备/取消、设备变化失效、统一开局门禁 |
| `scripts/VersusLobby.gd` | 两套输入边沿/重复计时；统一开始与返回；页面头尾、开始区域、提示 |
| `scripts/LobbyPlayerPanel.gd` | 各自立绘、角色/技能信息、角色按钮与准备按钮，只发本人操作信号 |
| `scripts/InputSettings.gd` | 按玩家查询输入、稳定设备分配和 lobby_route 有效性；不改变整个 InputMap 架构 |
| `scripts/Menu.gd` | 在进入双人选角时加载/打开准备室，设置页继续复用；单人选角沿用原界面 |
| `scripts/Main.gd` | 收到双人开始请求时复查菜单授权与主状态，将两个角色按 P1/P2 顺序交给 GameEngine |
| `tests/test_versus_lobby.gd` | 独立状态与实际场景/输入事件的回归测试，设置文件隔离 |

Menu 的 `_ready()` 仅实例化一次准备室并连接一次信号；重新进入只重置玩家状态。Input.joy_connection_changed 的连接有幂等检查。关闭、隐藏或启动后的准备室不再处理选角操作。

## 路由与状态

InputMap 原有 24 个动作继续保留：p1、p1alt、p1vs、p2 各六个移动/炸弹/技能动作。战斗继续使用 poll_player；全局普通菜单继续使用 poll_nav。双人选角不进入共享 poll_nav 分支，而通过 poll_lobby_player("p1"/"p2") 分别查询明确设备号的 Input 状态。

手柄设备 ID 不等于玩家编号。InputSettings 先保留显式设备，再保留仍连接的自动分配设备，最后给空位分配剩余设备。断开 1P 时不会把 2P 的手柄挪给 1P。

每个 PlayerChoice 独立维护 player_id、device_id、selected_character、is_character_confirmed、is_ready、控制有效性和绑定签名。两块预览节点分别引用各自的 PlayerChoice，不共享可变选择状态；Cfg 的角色内容只读。

设备或绑定签名改变时只撤销受影响玩家的准备。手柄专用模式在设备断开时不能借战斗用的键盘回退静默开局；自动模式可以重新用键盘准备，但原准备会先失效。重连后必须重新按下确认；一直按住 A 不会自动准备。

## 操作流程

- 手柄：左右摇杆/十字键选角，A 确认并准备，B/Back 取消本人准备。修改角色也会撤销本人准备。
- 键盘：1P 使用对战键位（默认方向键、Enter 准备、Shift 取消）；2P 使用自己的键位（默认 A/D、空格准备、F 取消）。重绑定后跟随设置。
- ↑ 可打开原有设置页；鼠标可分别点击任意一侧角色和准备按钮。
- 已准备的一方等待对方，不会锁住对方选择。双方准备后开始区域变黄，再按 Start、A/Enter 或点击开始。
- B/Back 在本人未准备且双方都未准备时返回模式；对方已准备时只提示先各自取消，不会擅自清掉对方准备。Esc 对应 1P 取消/返回。

统一 begin_game() 会重新刷新控制路由，检查两个有效控制方式、有效且不重复的角色、两名玩家都已确认并准备、准备室仍处于活动状态，且尚未开始。先设置 game_starting，再发开始信号。Menu 复核页面/可见性，Main 再复核主状态和授权，因此同时确认或同时 Start 不会重复初始化。
