## 四、已知差异

1. 原作 `.replay.json` 的哈希基于 JavaScript 通用对象图快照；Godot 版使用自己的状态哈希。原作回放可在游戏内兼容模式观看，但不显示“已验证”。
2. 无加载进度条；Godot 加载很快，直接进入菜单。
3. UI 与场景美术按原作绘制代码的坐标、字号、配色与形状逐点重绘（见"四之二、美术逐点复刻"），绘制调用已全面开启抗锯齿；余下的差异只来自渲染后端本身——字体度量与字形渲染、`font_size` 只能取整数、`draw_string_outline` 描边只能整数且向外扩。
4. 字体使用 Windows 的 Microsoft YaHei 作为 HarmonyOS Sans SC 的等价回退；拉丁标题/编号使用 Impact，等宽标签使用 Consolas。
5. 音效为预合成 WAV，而非 Web Audio 实时振荡器。
6. 页面失焦自动暂停尚未移植；音量、控制器和键位设置现通过 Godot `ConfigFile` 持久化。\n7. MCP 为 Godot 原生 stdio JSON-RPC，不依赖 Node/Python；工具集与 CLI 操作一一对应。

## 四之二、美术逐点复刻

移植时曾把"看起来一样"当成合格，导致一批绘制被写成近似：渐变被压成纯色或只剩两色、
`ctx.ellipse` 的旋转角被丢掉、贝塞尔被换成固定步数折线、`ctx.clip` 与部分描边整段丢失。
这一轮把这些全部按原作 `src/render/*.js`、`src/scenes/*.js` 的真实绘制命令重做。

新增共享图元层 `scripts/CanvasArt.gd`，用于精确重建 Canvas 语义：

| 能力 | 对应 Canvas API | 实现要点 |
|---|---|---|
| `bezier` / `quad` | `bezierCurveTo` / `quadraticCurveTo` | 按"控制点到弦距离"自适应细分（容差 0.06px），不再固定步数采样 |
| `arc_pts` / `circle_pts` / `ellipse_pts` | `arc` / `ellipse` | 按弓高决定段数，并支持 `rotation` 参数 |
| `fill_linear_gradient` | `createLinearGradient` | 渐变轴映射到 UV 后逐像素采样，**保留任意轴方向与全部中间色阶** |
| `fill_radial_gradient` | `createRadialGradient` | 按规范解双圆锥面方程，**保留偏心内圆的高光** |
| `ellipse_rot_stroke` / `ellipse_rot_fill` | `ctx.ellipse(..., rot, ...)` | 旋转角不再丢失 |
| `stroke_clipped` / `clip_polyline` | `ctx.clip()` | 折线求交裁剪（取内侧须用 `intersect_polyline_with_polygon`，`clip_*` 返回的是补集） |

被修正的典型偏差（每一条都对应原作某一行）：

- **地板**：每格其实是 `(x,y)→(x+TILE,y+TILE)` 的斜向渐变，且棋盘奇偶相位原本是**反的**。
- **森林硬墙**：三叶簇由"菱形"改回"直线 + `quadraticCurveTo`"并补描边；阔叶补回外轮廓描边、第二道高光、`ellipse(4,2)` 斑点与 `seed===0` 的果实。
- **古树**：树冠六团叶簇恢复共用的三段渐变 `(x,y-68)→(x,y+22)`；树干恢复斜向木纹渐变。
- **木箱木纹**：恢复 `(x,y)→(x+38,y+42)` 的三段斜向渐变（中点为 `#c49d6b`）。
- **礼物蝴蝶结**：两个椭圆恢复 ±0.4 弧度旋转，不再画成正椭圆。
- **工厂**：观察窗玻璃与钢壳恢复各自的斜向渐变；黄色带上的斜纹补回 `ctx.clip` 裁剪（此前会画到带子外面）；炉心辉光由三个同心圆还原为偏心径向渐变。
- **蘑菇丛**：伞盖改回"上半椭圆弧 + 一次 `quadraticCurveTo` 收口"并补描边。
- **道具泡泡**：恢复偏心内圆的径向玻璃渐变；七种道具图标全部改回原作的贝塞尔轮廓与真椭圆。
- **毒刺**：三叉横梁改回 `quadraticCurveTo`。
- **技能特效**：`soul_pulse` / `soul_awaken` / `flame_reflect` 整体重写（此前 `soul_awaken` 落到 else 分支只画一个扩散圆），并修正 `globalAlpha` 与颜色自带 alpha 需**相乘**的语义。
- **静态地图缓存**：恢复原作的 2× 超采样（SubViewport 1440×1248 + painter 缩放 2 + 贴图缩回 0.5），细线重新得到抗锯齿。
- **前景柔光微粒**：补回原作 `drawMap` 末尾的 14 颗粒子。
- **层序**：`drawPoison` 与 `drawBombZones` 的先后关系改回原作（毒刺在下、范围预览在上）。
- **传送带箭头**：`Scenery.nearest` 补回 `dx/dy`，箭头不再恒朝右。
- **菜单**：海报放射线/闪白/跑马灯补回 `ctx.clip`；唱片底影的 `ellipse(76,11)` 不再被 `scale(1,0.33)` 拉成 `ry≈25`；入场动画恢复原作的 `×5`/`×4` 推进与 1.0 夹取；设置面板补回缺失文案。
- **暂停 / 结算 / 关前档案**：卡片缩放动画不再被第二次 `draw_set_transform` 覆盖丢失；刊头与黑条补回圆角裁剪；彩带星形恢复二次旋转与淡入。
- **HUD**：死亡态的 `globalAlpha` 折进颜色 alpha（此前爱心、技能卡、道具图标没跟着变暗）。
- **角色立绘层序**：Godot 里 `Node2D` 自身的 `_draw()` 恒在子节点**之下**，而原作把立绘画在
  「落影 + 通灵轮廓」之后、「白闪 / 光环 / 护盾 / 星星」之前。原先用子节点 `Sprite2D` 渲染立绘，
  导致这些特效被整体压到立绘背后（**玩家无敌白闪被完全遮住**）。现改为在 `EntityView._draw()`
  里用 `draw_texture_rect` 画立绘（变换链与 `SoulGlow` 所在的 pivot 完全一致），
  `Sprite2D` 只保留节点、`visible = false` 退出渲染。
- **角色 / 敌人锚点与动效**：敌人脚底锚点原本把 `+2 / +8` 算了两遍（小怪低 2px、BOSS 低 8px）；
  玩家护盾气泡整段缺失；通灵轮廓光改为 SDF 柔光（见下）；1P/2P 标签偏低约 16px；逐角色 `motion`
  （未来 3/3/.025/.18、通灵形态 2/1.5/.012/.1）此前被统一写死成默认值。
- **通灵柔光（无 blur 图元）**：原作 `shadowColor/shadowBlur=10` 的柔光无法用 Godot 2D 图元直接等价。
  新增 `SoulSdf.gd` 把觉醒立绘的 alpha 轮廓烘成有符号距离场（正面 / 背面各一张，
  `assets/characters/*.sdf.png` 离线资产 + 运行时 chamfer 回退）；`SoulGlow.gd` 用
  「SDF 主光 + 紫墨晕 + 径向 bloom + 矢量法环 / 灵屑 / 觉醒爆发」组成完整柔光。
  主光每像素 3 次 SDF 采样（主轮廓 + 左右色散），墨晕 1 次；没有 blur pass、后处理、
  SubViewport 或全屏拷贝。实机为浅色地图把光强压到 `0.34`、墨晕 `0.60`、体积光 `0.35`；
  展示台 `soul_preview.tscn` 使用更亮的 `1.0 / 0.27 / 1.0`。觉醒的大闪白 / 光柱 / 软环在角色背后，
  星屑 / 集中线 / 半调点在角色前面，人物始终留在最上层。

- **补回整块缺失的效果层**：原作 `src/render/effects.js` 的**粒子 / 飘字 / 震屏**此前完全没有移植。
  现新增 `scripts/Effects.gd`，按原作数值逐点复刻：`burst` 的 7 次随机抖动序列、
  `explosion` 主爆（14 粒 / 速度 165 / 生命 0.42 / 重力 130 / lift 30）与末端火星
  （`step = max(1, floor(cells/3))`，每格 3 粒）、`death`（16 粒星形）、`enemyDeath`、
  `pickup`（重力 **−30**，走的是上浮）、`shieldBreak`（长条 `rect`）、`levelClear`（70 条彩带 + "过关！"）；
  粒子 alpha `min(1, a×1.4)`、半径随寿命收缩、`rect` 是 `2r × 1.1r`；飘字 `vy *= 0.93` 为**每帧**衰减、
  前 45% 不淡出；震屏 `maxShake = 7`（`explosion` 请求 9 会被截到 7）、`shakeDecay = 42`、
  偏移 `(rng−0.5)×amp×2`。接线只动 `Main.gd`：挂在 `Actors` 之后、每物理帧在
  `GameEngine.step()` **之后**喂一次事件（`step` 开头会清空 `world.events`，读取不清空，
  放在 `_process` 会重复消费）、震屏偏移加到 board/actors/effects（HUD 不晃）。
- **修掉 `scenery` 子类型被覆盖的既有缺陷**：`World.emit_event()` 会把 payload 的 `kind`
  覆写成事件名，导致 `Scenery` 传的 `"kind": "fruit" / "carousel"` 被冲掉，
  `Main._drain_events()` 的对应分支**永远匹配不到**（落果与木马的音效、横幅实际不播）。
  现改用互不冲突的 `"sub"` 键，`Main.gd` 与新效果层都已对齐。

- **关前档案的敌人立绘**：原作是 `hud.js:512-517` 把合成敌人交给 `sprites.js drawEnemy`
  并套 `translate + scale(1.85 / 2.55)`；此前只按高度等比缩放到 `feetY`，于是
  NPC 贴图宽度差了最多 1.8px（原作是**固定 52×48 非等比**）、BOSS 立绘整体高了约 10px，
  且丢掉了 `drawEnemy` 内部的 idle 呼吸（`sin(time*2.2)*1.1`）与落地阴影。现已把整条变换链
  合成回世界坐标逐项对齐。

- **全面开启抗锯齿**：Canvas 的 `stroke`/`fill` 一律抗锯齿，而 Godot 立即模式绘制默认
  `antialiased = false`。实测（`tests/aa_probe.gd`）确认关闭时**过渡像素恒为 0**（彻底硬边），
  开启后：填充圆 0→96、空心圆描边 0→212、斜线 0→122、圆弧 0→100。
  现已给 **163 处**绘制调用补上 `antialiased = true`（覆盖 `draw_line` / `draw_arc` /
  `draw_circle` / `draw_rect` / `draw_polyline`）。
  - 为什么不用 MSAA：`rendering/anti_aliasing/quality/msaa_2d`（即 `Viewport.msaa_2d`）
    **只有 Forward+ / Mobile 支持，Compatibility 不支持**，而本工程必须留在 Compatibility
    才能导出 Web。逐图元开关也正是官方推荐做法（"不需要启用 MSAA，基准开销很低"）。
  - **实测到的副作用**：`+0.5` 对齐的 **1px 细线**开 AA 后出现 31 个过渡像素
    （Canvas 在这种写法下是精确覆盖、保持锐利）；但 **1px 矩形描边**两边都锐利、不受影响。
    受影响的主要是描边网格线，且静态地图本身有 2× 超采样兜底，实际影响很小。
- **修掉一个严重的性能回归（"未来"放弹后卡顿）**：`CanvasArt._radial_texture()` 的缓存键里
  带了**绝对坐标**，于是每换一个位置就要逐像素重算一张径向渐变纹理：

  | 场景 | 修复前 | 修复后 |
  |---|---|---|
  | `soul_pulse` radius=2 冷启动 | 132.1 ms（≈8 帧） | 15.5 ms |
  | 换位置 100 次 | ≈13,200 ms | **0.47 ms** |
  | 道具泡泡（中心逐帧抖动） | 4.6 ms/**帧** | **0.021 ms/帧** |
  | 纹理缓存条目 | 随位置无限增长 | 5（常数） |

  改法是按外圆半径归一化，让形状与摆放位置解耦（把径向渐变二次方程的 a/b/c 同乘 r1²
  即可证明根不变，故画面完全等价），并把逐像素 `set_pixel` 换成
  `PackedByteArray` + `Image.create_from_data`。基准脚本：`tests/bench_radial.gd`。

- **静态地图拆成两层缓存（炸砖不再整张重画）**：`World.set_tile` 炸掉一块软砖会让
  `map_revision + 1`，而 `Board` 原先拿 `map_revision` 当缓存键 —— 于是**炸一块砖就把整张
  2× 地图重画一遍**。实测（`tests/bench_map_redraw.gd`，40 帧中位数）整张 45.20 ms，
  分段为：地板 13.71 / 硬墙 19.17 / 软砖 11.39 / 设施 1.19 —— 45 ms 里只有约 **12.6 ms**
  是真正变了的东西。
  现拆成两层：`base`（地板 + 环路 + 硬墙，只在换关时重画）与
  `dest`（软砖 + 中央设施 + 灯串，炸砖时重画）。为此给 `World` 加了 `map_identity` 计数
  （只在 `GameEngine.apply_level` 里 +1），它才是真正的"关卡身份"。
  - 拆层的正确性：原作 `drawMap` 的顺序是「地板 → 环路 → 逐格(硬墙|软砖) → 设施 → 灯串」，
    而硬墙与软砖**永不落在同一格**、各自画在自己格内，所以把硬墙整体提前画不影响可见结果。
    `tests/verify_map_layers.gd` 把「拆层合成」与「原作单遍顺序」逐像素比对：
    **三主题各 1,797,120 像素，差异 0 个，最大通道差 0.000**。
  - 注意这是**纯性能优化、不是复刻偏差**：原作 JS 同样是"任一格变化就整张重画"
    （`key` 里串了整张 map），拆层后画面与原作逐像素一致。

仍存在、且不伪装成已解决的差异：

- `UIDraw.text` 的描边宽度只能取整（Godot `draw_string_outline` 只收整数），且它是向外扩、Canvas `strokeText` 是沿字形轮廓铺开——同一数值下原作更贴字。
- `UIDraw.tag` 的 `rot` 分支使用绝对变换，会丢掉调用方的环境变换；Godot 没有"读取当前绘制变换"的 API，只能在调用方绕开。
- Godot 的 `draw_polyline` 没有圆角连接开关，折线接头仍是尖角（原作 `lineJoin/lineCap = 'round'`）。
- `font_size` 只能取整数，原作允许 7.2 / 6.8 这类小数，贴纸量宽有亚像素差。
- `CFG.SHOW_FUSE_TIMER`（引信倒数环 + 剩余秒数）原作默认为 `false`，移植版未实现该分支。
- 震屏已按原作 `effects.js` 的 `shakeIt` 实现（`maxShake = 7` / `shakeDecay = 42`），
  偏移作用在 board/actors/effects 上、HUD 不晃。
- 回放界面：原作是 DOM + CSS（`replay/view.js`、`style.css` 内无 canvas 绘制），没有可逐点对照的 Canvas 真值。

| 套件 | 覆盖 | 结果 |
|---|---|---|
| `test_core` | 地图 / 炸弹 / 道具 / 技能 / 赛制 / AI（纯逻辑） | `CHECKS=42 FAILURES=0` |
| `test_play` | 实跑对局：技能、BOSS 阶段、毒刺、传送带、木马、生命 | `PLAY_CHECKS=35 FAILURES=0` |
| `test_art` | **绘制路径**：三主题全格砖墙/设施/环路、MapPainter、Board 动态层（含 5 类技能特效）、七种道具图标、11 种角色/敌人/BOSS 配置、效果层的事件→粒子/飘字/震屏、静态地图分层缓存的键 | `ART_CHECKS=60 FAILURES=0` |

> `test_art` 是补上的空白：`test_core` / `test_play` 都不加载 `main.tscn`，
> **不会触发任何 `_draw()`**，渲染路径原本零覆盖。

> ⚠️ **但它的覆盖曾被高估，这点必须记下来**：加断言时实测发现，在无头 harness 里
> 手动发 `NOTIFICATION_DRAW` **并不会真的执行 `_ready()` / `_draw()`**
> （证据：`force_draw(board)` 之后 `_painter_base` 仍是 `null`、缓存键仍是空串）。
> 因此 `test_map_painter` / `test_board` 里 `check(true, "…绘制未崩溃")` 那种写法
> **只能证明"没有抛错"，不能证明"真的画了"** —— 它们在此之前一直是空过的。
> 现在新加的断言一律建立在**可直接读取的状态或纯函数**之上（例如把缓存键抽成
> `Board.layer_keys()` 静态纯函数），不再依赖"绘制已经发生过"。
> 绘制正确性改由离屏渲染工具保证：`tests/verify_map_layers.gd`（逐像素比对）、
> `tests/aa_preview.gd`（三主题出图）。**建议后续把那些 `check(true, …)` 逐个换成真断言。**

实机验证：开始菜单、选角、关前档案、森林 / 工厂 / 游乐园三主题、第 5 关 BOSS（试探/暴走）、暂停、结算、横幅、独立 Windows exe。


## 六、本轮接手：手柄、界面可读性与硬墙缓存（2026-10-18）

此节是最新验收结果。保留此前 AA、径向渐变与地图分层优化；为了可读性，菜单/HUD/弹窗字号与布局已经有意调整，不再宣称这些页面与原作坐标逐点一致。

### 手柄修复

- 显式选择的已连接手柄优先分配；自动分配使用剩余设备。两名玩家不会共用同一手柄；单人模式不会让未上场的 2P 占用设备。
- 设备离线时不再返回无效设备号；手柄专用模式在离线时回退键盘。菜单允许所有连接手柄操作，避免选了键盘后无法用手柄恢复设置。
- 手柄绑定冲突只在同一玩家内判断；两名玩家可以各自使用相同按钮。Start / Back / Guide 保留为系统导航按钮，拒绝新绑定占用。
- 页面打开、暂停恢复、关前确认时同步按键状态；按住确认不会跳过档案或在战场上误放炸弹。改绑结束后等待松手，避免取消或捕获的按钮继续触发导航。
- 设置页可聚焦“完成”；滑杆离开焦点/关闭设置时保存。Back 可取消改绑，键盘 Del 可清除键盘或手柄绑定。
- 结算页支持左右选择、A 确认与 B 返回；回放页支持手柄选择回放、播放暂停、跳转、倍速和返回。Start 只接受上场玩家分配到的手柄。
- HUD 的手柄放弹/技能提示使用实际绑定，修正对战 1P 错读 p1vs 手柄绑定的问题；键盘操作不会额外触发手柄震动。

### UI 与画面问题

- 菜单、设置、档案、暂停、结算、回放及 HUD 的小字大多提高到 11 个逻辑像素以上；技能说明使用 12px 与更宽行距，键帽也加大。
- 长设备名与技能键名按字体真实宽度布局/截断；重写换行函数，修复一行限制仍输出两行、省略号超宽和显式换行的问题。
- 调整控制器设置中 2P 设备说明、死区、震动与页脚的间距；去除回放按钮双语文字重叠。
- 修正选角页旋转放射线的裁剪坐标，避免装饰越过海报遮盖其他控件；跑马灯重复间距按真实字宽计算，装饰星星移开技能键帽。
- 普通对局计时/关卡卡片收进顶部硬墙边框，技能卡收进底部边框，减少遮挡可行走格。
- 发现并修复 BOSS 暴走破墙后的画面残留：新增仅用于渲染的 hard_revision，使 base 层在硬墙变化时刷新；普通炸软砖仍只刷新 dest 层。
